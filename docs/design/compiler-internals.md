# Compiler internals

*Part of the [design sketch](design-sketch.md), beside [Compiler architecture](compiler-architecture.md). How the compiler implements each command and feature, for whoever changes it; [the guide to the compiler](../../compiler/README.md) gives the pipeline, the query database and where to start. Paths in backticks are relative to `compiler/`.*

## The query database and parallel work

The database's inputs have the durability of how often they change (`stilt-db`): a program file's contents change with each edit, the list of a program's files when a file is added or removed, and a file's place and the standard library never, so an edit never proves unchanged what read only the standard library. Every file of the program keeps the same durability, since salsa can't keep the result of a query whose inputs lost durability: a file made more durable until its first edit would have that edit check again every body that reads it. An edit thus has salsa prove unchanged, by what each read, every result that read a program file, each function's MIR among them, and the walk of a running program's code below does the rest of its work in proportion to the edit. A database makes the standard library once, and every program it holds shares it. Each module's names come from its files' places alone, its scope is a query of its own, and so is what its scope says of each name that another module looks up there, so adding an item, or a variant to a type, resolves again only the modules that look that name up in its module, or that read the whole scope to suggest a name where a lookup failed (`stilt-hir/src/scope.rs`, `scope/names.rs`). `stilt_types::check_in_parallel` checks a program's bodies across the machine's cores, or `STILT_THREADS` of them, in waves, each thread with its own handle on the database (`stilt_db::parallel`): every file is parsed, every module resolved, every body type checked, the implicit effects found when a `without` reads them, and every body's diagnostics found; `check` then gathers them in its own order, so the result is the one checking in order gives, byte for byte. `build` and `run` also lower what the entry reaches a step of the walk at a time, each step in parallel, summarize in parallel what each function reached consumes, and count the changed functions in parallel; since what a function consumes follows only its own body and the functions it passes parameters to, which it reaches, they never summarize the rest of the program or of the standard library (`stilt-rc/src/queries.rs`). Cranelift then compiles them in parallel (`stilt-codegen-clif/src/compile.rs`): `run` translates each function into Cranelift's IR in turn, since translating declares what it names, and `build` translates each apart, across the machine's cores, into a draft of the module that numbers what the translation declares on its own, and compiles it on the same thread, while it asks the module, in the order of the functions, what each draft asked as soon as it is translated (`stilt_db::parallel::map_costly_alongside`), which declares everything as translating in turn does, and relocates the draft's code against the answers (`stilt-codegen-clif/src/draft.rs`); each function's IR is checked once by Cranelift's verifier, rather than again after each of Cranelift's own passes, and compiled into machine code on any thread, the largest first, and its code defined in the order of the functions, so that the object file or the image is the same byte for byte whatever the number of threads; a clean build of the 100K-line project takes about 0.9 s. `stilt_db::parallel::map` gives each thread the next item as it finishes one, since functions differ in cost, and `parallel::map_costly` starts a thread for each item, up to one per core, for work that costs more than starting one, as compiling or counting the few functions an edit changed does. A query that checks a body keeps the declarations it looked up, since each lookup through the database contends with every other thread's (`stilt_hir::decls::QueriedOnce`). The commands don't free the database at exit, which the system takes back faster. The incremental tests are in `stilt-db/src/tests.rs`, `stilt-hir/src/tests.rs` and `stilt-types/src/tests.rs`.

## The engine

`stilt engine PATH` holds the program's database in a process of its own, and answers `check`, `build`, `run`, `show` and `test` from it, so that a build or a run right after a check runs no query of the front end again (goal `one-engine`; `stilt-cli/src/engine.rs`). It listens on a socket named after the program's canonical path and the toolchain's version, in a directory of the user's own under the system's temporary directory that no other user may open, beside a lock file it holds for its life, so that a second engine of that version never holds the same program, and each end of a connection checks that the other runs as the same user ([engines.private](../../reference/19-tools.md#engines.private), [engines.toolchains](../../reference/19-tools.md#engines.toolchains); `stilt-cli/src/engine/private.rs`). `check`, `build`, `run` and `show` on a directory program ask the program's engine, and print its report, which is the one they would have printed: the engine runs the same code on the same files, from the client's working directory. A command that finds none starts one, in a process group of its own, and waits for it to listen: on the 100K-line project, a first `check` takes as long as one in the command's own process, within the noise of the machine, since the engine does the work the command would have done. Commands that start at once start one engine, because the lock file lets one engine hold the program, and the others end and leave their commands to connect to it. A program of one file has no engine for them, and runs in the command's own process, as does a command whose engine can't answer, as when it is another build of the compiler's; `test` asks the engine of every program, a single file included, as below. Tests and recipes that run commands on directory programs stop the engines they start with `stilt engine --stop`. Before each command, the engine takes in the edits made to the program's files since the last: a file whose time of change or size differs is read again, and a file added or removed reads the program again (`stilt-cli/src/sync.rs`, which `run` shares). Taking edits in writes to the database, one command at a time; every command then answers from a handle of its own, so several answer at once, and a write cancels the commands answering, which take the edit in and answer again. Each write is a revision of the program. An engine stops once no command has come for its idle time, two minutes unless `--idle` says otherwise, or when `stilt engine --stop PATH` asks it to; `stilt engine --ran PATH` prints the queries that an engine started with `--record` has run since that was last asked. An engine's cache stays bounded (goal `bounded-cache`): it keeps the syntax trees of the 64 files it read last (`stilt_db::keep_trees`), which the queries after the parse need again only when a file changes; a module's resolution is never compared with the last, so that its projections, `module_hir`, `module_body` and `body_starts`, run again with it and share its new parts rather than hold an older copy (`stilt-hir/src/lower.rs`); and consumption summarizes only the functions that a build reaches, or that a function `show` asks about reaches, from the MIR kept of them (`stilt-rc/src/queries.rs`), so the database keeps the MIR of only those functions; the counting and the machine code that the engine keeps for its next build are those of the functions its last build reached (`stilt_cli::build::Kept`). Once a build or a run has lowered its code, the engine keeps the typed bodies of only the 64 bodies it read last (`stilt_types::keep_typed`, `stilt-cli/src/engine/server.rs`): only an edit, which checks the bodies it changes again, or a command that reads a body's types needs one again, and a check, whose build reads them all, forgets none; checking a program in parallel proves each body checked by a small result of its own, `broken`, without reading its typed body (`stilt-types/src/parallel.rs`). The HIR of every body stays, since an edit compares each body of the file it changes with the last and finds most of them unchanged, which a forgotten body can't be. A name is four bytes, interned once for the process with its text, which it hashes and orders by, as a string does (`stilt-hir/src/hir/name.rs`), and the trees the database keeps, the HIR, the typed bodies and the MIR, have no spare room in their vectors (`stilt_hir::hir::fit`). On the 100K-line project, the engine's cache after a build is about 275 MB, most of it the modules' resolutions, and about 30 MB the counting and machine code kept for the next build. `just latency` builds the 100K-line project by way of an engine, replays the edit script on it ten times, each edit checked by the engine and each replay ended by a build, and fails when the engine's cache, the memory its allocator holds in use, is 1 GB or more, or grows from the first replay to the last; it prints the process's physical footprint beside it (`tools/latency/src/memory.rs`). A program runs in `run`'s process, but its code comes from the engine (`stilt-cli/src/engine/server/runs.rs`): `run` sends the command `run`, and the engine lowers the program's code as `run` alone would, each function the entry reaches with its reference counting, and answers with it, with the diagnostics of a program with errors first and its code with an error made to panic. `run` compiles what it receives into its image. Then, at each look at the program's files, `run` asks again on the same connection, and the engine takes in the edits and answers with what changes in the run since its last look, whichever command took the edits in: nothing, the diagnostics of an edit that leaves errors, or the functions whose code changed and whether the layout of the program's values did, which `run` patches in, or starts the program again for, as it does alone. Each run keeps its own record of the code its image holds, and its own walk of what the program's entry reaches, and every run shares the engine's reference counting, so that a run after another counts only what an edit changed: on the 100K-line project, whose program ends at once, a run whose engine has checked the program takes 0.65 s, the engine giving it its code in 0.4 s, and the next run 0.24 s, its code given in 20 ms, where `run` alone takes 1.25 s. Several runs and checks are answered at once, each from a handle of its own. Each look is a command of its own, so a running program keeps its engine from idling; once the engine is gone, the run goes on without patching. Every message is a frame, a magic word, the message's length and the message in postcard's compact binary form, which serde writes from the MIR's types: 1.7 MB for the 100K-line project, a seventh of its JSON (`stilt-cli/src/engine/wire.rs`). Its tests are in `stilt-cli/tests/engine.rs`, and those of the engines that commands start in `stilt-cli/tests/engine_start.rs`, and `just engine` runs the conformance suite, the guide's examples and generated programs with each check, build, run and test answered by an engine started for its program, through `tools/runner/engine.sh`: each check reports what the compiler alone reports, each run test, built by way of an engine and run, and run by `stilt run` with the code an engine gives it, through `tools/runner/engine-run.sh`, gives its expected output, as each test-block test gives its expected results, and each generated program, run with the code an engine gives it, gives the run that the compiler alone gives.

## The language server

`stilt lsp` is the language server (goal `one-engine`; `stilt-cli/src/lsp.rs`, `stilt-lsp`, and `stilt-ide`, whose answers it gives): it speaks the protocol to an editor on stdin and stdout, and asks the engine of the folder the editor opened, starting one when none runs. The text of each buffer the editor opens or changes replaces its file's in the engine until the editor closes it (`stilt-cli/src/sync.rs`), so `check`, `build`, `run`, `show` and `test` read it too, and each change publishes the diagnostics of every file, with their fixes as quick fixes (`one-diagnostic-shape`), a diagnostic's only fix its preferred one and every fix of a file at once as `source.fixAll.stilt`, their notes as related information, and their tags: a hole is information, a stale doc deprecated, and code that does nothing unnecessary. Changes that arrive together publish once, before any request after them is answered, and so does a change the editor reports to a file it watches on disk. A hover shows a variable's inferred type, with `let`, `var` or `inout` as it is bound, a parameter where it is declared, a field's type, a type's definition, that of a variant's type where a pattern names the variant, or a function's header with its facts, with the doc comment in Markdown and its examples as code, and over a macro's use, its expansion, which a use whose macro failed has none of ([macros.showing](../../reference/16-meta.md#macros.showing)); over a keyword, a built-in effect, a limit or a primitive type, the form it is written in, what it means and the record that defines it (`stilt-ide/src/editor/words.rs`). A definition, and a declaration, is a variable's binding or the name of the declaration the code names (`stilt_types::position`, `stilt-ide/src/show/position.rs`), and a type definition the declaration of its type. The rest reads what `stilt show` and checking compute (`stilt-ide/src/editor/`): completion offers the variables in scope, read off the syntax tree so that a body with a syntax error has them, the items of the module, the prelude and the imports, a value's fields and methods, a type's variants, a module's `pub` items, the modules after `use` and the keywords that may stand there, inside a macro use's groups as in an expression where the use is (`editors-see-expansions`, `expansion-survives-broken-input`), each with its signature or type beside its label, and, where the editor expands snippets, a call with a placeholder for each parameter, a variant with one for each payload and a keyword with its construct (`snippets.rs`); after a `.` whose function no longer parses, the engine checks the file once more with the `.` taken out, holding the program meanwhile, to find the receiver's type; signature help finds the call among the tokens; references and renaming resolve each word that spells the name, a method of a trait impl standing for its trait's, and refuse the standard library's names and keywords, and a name's highlights in its file tell the places that bind or assign it from those that read it (`access.rs`); symbols are the declarations of the syntax tree, an impl's members nested; inlay hints are the types and the facts `show` writes in, each fact with what it means and the lines that cause it, the first of which a click on it goes to, and at the end of each line that causes a fact, what it does there, as `show` writes it in a comment ([modes.show](../../reference/13-modes.md#modes.show); [facts.visibility](../../reference/15-facts.md#facts.visibility); `hints.rs`, `stilt-ide/src/show/facts/listed.rs`); and semantic tokens classify each word by the tree and the variables checking resolved, keywords that direct control apart, built-in effects apart from those a program declares, and a string's escapes, interpolation braces and format specs apart from its text, as the editor's grammar does so that colors don't change when they arrive (`tokens.rs`). Folding and selection ranges, a file's outline and its formatting, by `stilt fmt`'s formatter, need only its text and are answered without the engine. Code lenses, offered to every editor but Visual Studio Code, whose extension runs tests and programs itself, run `stilt test --json` above each test and doc example and `stilt run` above `main`, each a process read on threads of its own so the server answers as it runs and the lens of the job running stops it; the results show beside their lenses until a file changes (`stilt-lsp/src/jobs.rs`, `stilt-ide/src/editor/lenses.rs`). Each answer names its engine's process, and an engine started after an idle one stopped is given every open buffer first. A server whose own executable another build replaced, as an update does, stops with a message on stderr, since it can reach no engine of its build, and the editor starts the new build's ([engines.toolchains](../../reference/19-tools.md#engines.toolchains)). Its tests are in `stilt-cli/tests/lsp.rs`, `lsp_writing.rs`, `lsp_navigation.rs`, `lsp_reading.rs`, `lsp_lenses.rs` and `lsp_macros.rs`, and in `lsp_compile_time.rs` over the compile-time benchmark of `bench/compile-time/` (`editors-see-expansions`), and `just latency` replays the edit script through it on the 50K-line project, 100 edits of each kind, waiting after each until every file's diagnostics are published, so that no edit's wait ends on those of the edit before (`edit-to-diagnostics`). The extension of `editors/vscode/` is its client.

## Checking against the reference interpreter

`just parse` and `just check` compare the compiler's syntax trees and diagnostics with the interpreter's. `just run` runs the conformance suite's run, check and test-block tests, and the guide's examples, under `stilt run` and `stilt test`, and `just differential` runs generated programs and their tests under both and compares their output and their tests' results (goal `debug-runs-like-interpreter`).

## Tests

`stilt test [--json] PATH` runs every test, doc example and property of a program without errors, and reports a result for each, in the order of their files' paths and then of their lines, after the program's diagnostics ([program.test-results](../../reference/04-programs.md#program.test-results), [program.running-tests](../../reference/04-programs.md#program.running-tests) and [program.doc-examples](../../reference/04-programs.md#program.doc-examples); `stilt-cli/src/test.rs`). It asks the program's engine, a program of one file included, and starts one when none runs, since the engine remembers what each run left (`stilt-cli/src/engine/server/tests.rs`): the engine checks the program, lowers the entry of each test and doc example (`stilt_mir::FnRef::TestEntry`), which calls its body and gives 1 when the test passes, and sends the code of the tests to run with their reference counting; `test` compiles it into one image in its own process, runs the tests, and sends the results back. The tests run one after another, each on a thread of its own (`stilt_runtime::test`): a panic or an `exit` reports as in a watched run, then leaves its thread waiting until the process ends, with the objects it held, and fails only its test; a stack overflow or running out of memory ends the process with `fatal: <reason>` and status 134, so that no test reports a result, and leaves the engine as it was. When every test that ran passed, no thread holds an object, so `test` releases the constants the tests computed (`Image::release_constants`) and checks that every count is back to zero, reporting a leak as a run does, with status 70 (goal `no-leaks`). This compiles the program once for all its tests, where a process for each test would start, and compile, once a test, at the cost of the memory that the threads of failed tests keep; what the tests print goes to stderr. The engine keeps the result of each test that doesn't do `io`, as inference finds it (`stilt_types::tast::Tested`), by the hash of the code of its entry and of every function the entry reaches, so a later run reuses it while that code hashes the same; and the hashes of the program's files for each run whose verdict wasn't done, until it stops. With `--json`, `test` writes one object: the diagnostics and the results of [conformance.test-objects](../../reference/01-conformance.md#conformance.test-objects) and [conformance.diagnostic-objects](../../reference/01-conformance.md#conformance.diagnostic-objects), with `done` when there are no errors and every test passed, and `repeat` when the program's files are those of an earlier run whose verdict wasn't done (goals `one-verdict` and `repeated-failures-flagged`; [Agent syntax](agent-syntax.md)). Without an engine to answer, `test` holds the program in a database of its own and reuses nothing. The conformance runner stops the engine after each `test`, as it does after each command on a directory program. Its tests are in `stilt-cli/tests/verdict.rs`. A property ([tests.property-checking](../../reference/19-tools.md#tests.property-checking)) is checked as an example is, with its parameters' types made into a graph of the types they hold, which rejects those that can't be generated (`stilt_types::generable`), and its entry (`stilt_mir::FnRef::PropEntry`) takes the closure from the property's body, reads the values of a run from a tape, building each as code of its type builds it, and calls the closure. `test` generates and shrinks the values as data, exactly as [tests.draws](../../reference/19-tools.md#tests.draws), [tests.shrinking](../../reference/19-tools.md#tests.shrinking) and [tests.shrink-candidates](../../reference/19-tools.md#tests.shrink-candidates) fix them, writes each run's to a tape, and runs the entry with it on a thread of its own (`stilt_runtime::property`), whose panic reports nothing and fails only that run (`stilt-cli/src/test/prop.rs`). Inserting a map's entries calls its key type's `hash` and `eq`, so the tape notes which entries a key equal to an earlier one replaced, and `test` shrinks the maps that the program built (`stilt-cli/src/test/prop/tape.rs`). The result of a property is kept by the hash of its text with its code, and its object in `test --json` has the field `property` of [tests.property-verdict](../../reference/19-tools.md#tests.property-verdict). Its tests are in `stilt-cli/src/test/prop/tests.rs`, against values worked out by hand from the record, and `stilt-cli/tests/properties.rs`.

## Programs with errors

`stilt run` runs a program that has errors ([program.programs-with-errors](../../reference/04-programs.md#program.programs-with-errors)). It reports the diagnostics on stderr first, as `check` does, then runs the program, and exits with status 2 however the program ends; `build` keeps refusing a program with errors. `stilt-cli/src/errors.rs` finds the code with an error: each body in whose declaration an error lies, counting the errors that the root-cause rules of [errors.root-causes](../../reference/18-errors.md#errors.root-causes) leave unreported, and each body that meets the error type, through its signature, its impl's header or a declaration it uses (`stilt_types::meets_error_type`). Each panics with `check-error` as soon as it is called or read, at its name, and so does each method that a trait impl lacks, at the impl's `impl` keyword. A file with a syntax error is read an item at a time: the parser cuts its tokens before the keywords that begin items, and before the words that other languages begin a declaration with, as `def` and `struct`, and parses each part alone, and a part with an error keeps the item it begins, as far as the rule allows (`stilt-syntax/src/grammar/recovery.rs`). The first syntax error that `check` and `parse` report doesn't change. Its message says what the grammar expected there and what it found, and where the tokens are another language's way of writing a form, such as `let mut`, `->` in a `match` arm or `===`, the form that Stilt writes, with the fix (`stilt-syntax/src/foreign.rs`). A name that doesn't resolve and that another language writes for what Stilt writes otherwise, as `null`, `this`, `String`, `len(xs)` or `println!`, says the Stilt form the same way (`stilt-hir/src/lower/foreign/`). Its tests are in `stilt-cli/tests/errors.rs`.

## Consumption

A function consumes a parameter when its body returns it, stores it in a value, rebinds it with `var`, passes it to a parameter that its callee consumes, or takes it apart to build in its place, a `match` on it that builds a value of its recursive type ([values.consumed-parameters](../../reference/05-values.md#values.consumed-parameters)). `stilt-rc` infers it from each function's MIR, where lowering borrows every `let` parameter, and the last from its typed body (`stilt-rc/src/consume/apart.rs`): the query `consumed` gives a function's share of a fixed point over every body of the program and the standard library, solved one strongly connected component of the call graph at a time. Each function owns what it consumes, and a direct call gives it those arguments, so a caller that passes its last use of a value lets the callee change it in place; every other parameter is borrowed. A caller that keeps using the value, after the call or in the call itself, loses that reuse: reference counting copies the value before the call, so the callee gets it still shared, and `stilt_rc::losing_reuse` gives each such call, which `stilt show` prints. A variable that lives in memory, because a pointer to it is taken, as one that `push` grows or an `inout` argument passes, gives its value up at its last use in the same way, and so does each word of the value an `inout` parameter points to: `stilt-rc` finds the words in memory that may be read again after each statement (`stilt-rc/src/slots.rs`), a slot by its name, any word through a pointer to it, which every use of the pointer counts as but computing another pointer from it, and through the locals that borrow from it, on any path, a new value for the slot ending the need. An `inout` parameter's words are read again where the function returns or raises, which gives them back to the caller, and nowhere a panic ends it, and a store through a pointer to one of them alone ends the need for it ([values.inout-arguments](../../reference/05-values.md#values.inout-arguments)). A statement that consumes a slot nothing reads again takes its reference without a copy and clears the slot, so that the release at the function's end finds nothing, or, in a block that ends the function with no later write, leaves the release out; a load of a word of an `inout` parameter's value into a local that keeps it, when nothing needs the word after, takes the word's reference in the same way and clears the word, so that the store that gives it a new value releases nothing. A word whose pointer is stored, returned or passed as a value is never handed over, and a variable or an `inout` parameter read after the call, or an `inout` parameter that goes back to the caller unassigned, is copied and reported as a lost reuse, as a value in a register is. Calls through closures, function values and dictionaries borrow every `let` parameter, and the code that a function value or a dictionary's entry holds calls the function directly, giving it what it consumes, as Lean 4's boxed versions do. Natives consume nothing. Type checking never reads the fact, so editing a body never checks its callers again ([facts.interfaces](../../reference/15-facts.md#facts.interfaces); [types.inferred-per-body](../../reference/07-types.md#types.inferred-per-body)). Its tests are in `stilt-cli/tests/consumption.rs`, and those of a variable in memory in `stilt-cli/tests/counting.rs`.

A value that the code takes apart is built again in place, as Perceus reuses memory (`stilt-rc/src/reuse.rs`; [values.consumed-parameters](../../reference/05-values.md#values.consumed-parameters)). Once the counting is inserted, the release of a local whose fields the code reads, a data object of `n` words, keeps the object's memory when it was the last reference, and the first data object of `n` words that each path after it builds is built there; memory that no object takes goes back before the function returns or raises, and before the release keeps more in a loop. Whether the memory is kept is the runtime's test of the count, where the release was (`stilt_rt_reclaim`, inline in `stilt.h` for a release build; `stilt-runtime/src/object/reuse.rs`), so a value that something else still references is released as before, and nothing a program does changes. The copies of the fields that the code read move forward, into the branches, to the release, which hands them over instead of releasing them, as Perceus's drop specialization does, so that a node taken apart and built again in place counts nothing: `stilt show --release` reports for the `ins` of the Perceus paper's red-black tree 3 operations and no copy, where it reported 12 and 10. Lowering marks each read of a field of a declared type's object with its variant, its tag and, when no word of it holds a type parameter's value, its layout word (`stilt_mir::mir::Variant`); a release that every path reaches through such reads knows the object, and its test is then of the count alone, one load and a compare, its other heap words released by code that names them (`stilt-rc/src/reuse/known.rs`). A node built in the memory of one of the same variant writes no header, and no field that holds the word the old node held there, as a field read from it and put back in its place does, which only an object that the pool gives writes (`stilt_mir::mir::Kept`): the `ins` that builds `Node(Red, ins(l, k, v), kx, vx, r)` from the node it took apart writes one word. The program retires 11.5 billion instructions, where it retired 77 without reuse, against 9.2 for Rust linked with mimalloc. A box, the runtime's own objects and an object that holds a function's code are built as before. Its tests are in `stilt-rc/src/reuse/tests.rs` and `stilt-runtime/src/object/reuse.rs`.

## The formatter

`stilt fmt [PATH]` writes a file, or every `.lt` file under a directory, by default the working directory, in the canonical format of [syntax.format](../../reference/03-syntax.md#syntax.format) and [syntax.no-options](../../reference/03-syntax.md#syntax.no-options), in place, skipping the entries whose names start with `.` (`stilt-cli/src/fmt.rs`). It prints the path of each file it rewrote, leaves a file with a syntax error as it is and reports its first error as `parse` does, and exits with status 1 unless every file was already canonical, so that a check fails on code that isn't. It takes no flag: the formatter has no options ([syntax.no-options](../../reference/03-syntax.md#syntax.no-options)), and a check is a run that rewrites nothing. `stilt-fmt` walks the lossless tree into a stream of tokens, each with the gap before it: the gaps that [syntax.format](../../reference/03-syntax.md#syntax.format) decides break the line always, as between statements, items and arms, which it writes with no `;` or comma between them, or where their group doesn't fit in 100 columns, as inside a short block or a type declaration, and every other gap breaks where the source does, as `gofmt` keeps the line breaks of expressions, lists and signatures and never wraps a long line. A group goes on one line when nothing in it forces a break, as a gap between statements or a comment does, and the whole line fits: the code up to it, the group, and the rest of the line up to its next possible break, comments that end lines aside. Each bracket indents the lines inside it a level deeper than the line it opens on, an element of a list or a block starting at that level and a line that continues one a level deeper. Comments stay on their lines, blank lines are kept, at most one, but after an opening bracket or before a closing one, a trailing comma stays only where its closing bracket starts a line, a statement that only a `;` could separate from the one before, as one that starts with `.` or `|`, goes in parentheses, and an impl or a trait keeps one member on the line of its braces if the source puts it there (`stilt-fmt/src/lib.rs` lists these choices, which [syntax.format](../../reference/03-syntax.md#syntax.format) leaves open). Before it returns, the formatter parses what it wrote, and refuses it unless its tree form and its comments are the source's. Its tests are the pairs of `tests/format/`, whose outputs are derived from [syntax.format](../../reference/03-syntax.md#syntax.format) by hand, and `just formatter` runs them with the properties of formatting the conformance suite, the guide's examples and generated programs: a second formatting changes nothing, and the tree that `parse --sexp` prints is kept (`stilt-fmt/tests/formatting.rs`); the command's own tests are in `stilt-cli/tests/fmt.rs`.

## `stilt show`

`stilt show ADDRESS [PATH]` prints what the address names in the program at `PATH`, by default the working directory's (goals `shown-facts` and `short-messages`; `stilt-cli/src/show.rs`, its views from `stilt-ide/src/show.rs`). A diagnostic code, such as `E0404`, shows its entry in the registry and the text of the paragraph of the Reference that defines it, its home. A module, such as `main`, shows as its skeleton: the header it writes, if any, and its imports, each on one line, then each declaration's doc summary and signature, without bodies, tests or doc examples, as `tools/measurements/token-cost/` measures it. A function, such as `main.totals`, or a method by its type's or trait's name, such as `main.Stack.pushed`, or by both for a method of a trait impl, such as `main.Stack.Show.show`, shows under its module's header with the module's tier written in, as in `module main [core]`: the tier its features need ([program.module-tier](../../reference/04-programs.md#program.module-tier)), `meta` for a module that declares a macro or writes `quote`, and not for one that only uses a macro ([macros.meta-tier](../../reference/16-meta.md#macros.meta-tier)). The function's facts follow its signature in brackets, as in `[consumes xs, alloc]`, and each line that causes one ends with a comment that says what it does there, as the errors of the limits say it, such as `` // `List.push` allocates `` ([facts.visibility](../../reference/15-facts.md#facts.visibility)). A check that a rule of acceptance proves shows as `proved bounds`, `proved divide-by-zero` or `proved missing-key` in the brackets, and its line's comment says it, where a `panic` would have been, followed by the rule's name, as `proved bounds by a range loop`, and with `--json` as an entry of `proved` with the rule under `rule` ([facts.shown-proofs](../../reference/15-facts.md#facts.shown-proofs)). A call that loses reuse, because it consumes a place that the function uses after it or passes to it twice, or an `inout` parameter that goes back to the caller unassigned, ends its line with a comment that names the place and why, such as `` // `xs` is used after this call, so `append_all` can't reuse it `` or `` // `table` goes back to the caller when the function returns, so `start` can't reuse it `` ([values.passing-values](../../reference/05-values.md#values.passing-values) and [values.inout-arguments](../../reference/05-values.md#values.inout-arguments)): a fact of its own, shown only at the call, which adds nothing to `alloc`, since [facts.allocation](../../reference/15-facts.md#facts.allocation) doesn't list it. Each `let` and `var` whose pattern writes no type has the type that inference gives it written in, as in `let xs: List<i64> = [1, 2]` ([types.inferred-per-body](../../reference/07-types.md#types.inferred-per-body)), from `stilt_types::facts::local_types`, which reads the typed body. The facts are read from the queries that compute them for the rest of the compiler: `stilt_rc::consuming` finds where a function's MIR uses each parameter that `consumed` says it consumes; `stilt_rc::losing_reuse` counts the references of the function's code and of its closures as a build counts them, and reads the copies that the counting makes of an owned local, a slot or a word of an `inout` parameter's value that a direct call consumes, before the call; and `stilt_types::facts::effect_causes` reads the implicit effects of the program and the operations of the body, as the limits of `without` do. A function whose body has an error has no facts ([facts.bodies-with-errors](../../reference/15-facts.md#facts.bodies-with-errors)), which `show` notes on stderr. With `--expanded`, `show` prints each macro use's expansion in its place, on one line, each name its template binds written with `#` and the number of its expansion, as `tmp#1`, which no program can write ([macros.showing](../../reference/16-meta.md#macros.showing)), and each fresh name of a procedural macro's expansion numbered in the order its binding appears there; the use's line ends with the lines its expansion takes in the canonical format, as `` // `swap!` expands to 5 lines `` ([macros.showing](../../reference/16-meta.md#macros.showing); `visible-expansion-size`). Without it, a use is printed as written. An error that a template's own tokens cause is reported at the use, with a note at the template when the macro is declared in the same file, and one that names the template's text otherwise ([macros.errors-in-expansions](../../reference/16-meta.md#macros.errors-in-expansions); `stilt_hir::hir::Expansion`); one at the user's tokens of a use's parts, which only the expansion checks, is reported there, with a note at the use's path that names the macro ([macros.errors-in-expansions](../../reference/16-meta.md#macros.errors-in-expansions); `compile-time-errors-at-user-code`). With `--json`, a code, a function and a module each show as one JSON record, a module's with its tier and the records of its functions, and each fact with its line and what causes it there, the parameter consumed under `param` and the place a call that loses reuse is given under `place`, and a function's record lists under `locals` each pattern that writes no type, with its line and its type. Its tests are in `stilt-cli/tests/show.rs`, and `just facts` checks the facts that it shows of the suite in `tests/facts/` against those the Reference gives. An address of a part ([edits.parts](../../reference/19-tools.md#edits.parts), [edits.paths](../../reference/19-tools.md#edits.paths) and [edits.body-addresses](../../reference/19-tools.md#edits.body-addresses)), a declaration's path or `PATH/body` for its body, with a hash or without, shows the part: a function with its facts, and a type, trait, constant, test or body as its canonical text, with `--json` as a record with `at`, `text` and `body` ([edits.showing-parts](../../reference/19-tools.md#edits.showing-parts)); an address with a hash that isn't current is refused with status 2. `stilt check` and `stilt test` take `--edit ADDRESS TEXT` (`stilt-cli/src/edit.rs`): every edit is checked against the files on disk, by its address, its hash and by whether its text parses as the part (`stilt-edit`), none applies if any is refused, which is reported with status 2 and no verdict, and otherwise each file is locked while it is read again, spliced and written, so that of two commands that edit one part from one hash, one applies. Each diagnostic of `check --json` has `at`, and each fix `edits` as `{at, new}` objects (`stilt-ide/src/at.rs`). The snapshots of refusals in `tests/diagnostics/` have an `edits` file beside the program.

## Values stored inline

Values are stored inline ([facts.allocation](../../reference/15-facts.md#facts.allocation); goal `inline-values`). A value is the words of its type's layout (`stilt-mir/src/layout.rs`): one word for a scalar, a string, a list, a map, a closure, or a value of a recursive type, and for a record, a tuple or a variant whose type isn't recursive, its fields' words in order, an array of more than 16 words being one local that holds them all in the frame (below). Where a type parameter stands, in a field that a declaration types with a parameter, a tuple's element or a type argument, a value is held in the words of its layout too, whatever its size, so an `Option<P>` is a tag and the words of a `P`. A variant type's first word is its tag, the immediate of the variant's index, and its variants' payloads share the words after it by class: scalars, then heap words, then each type parameter's words, so an `Option<i64>` is two scalar words, and a type whose variants have no payload, such as `Ordering`, is its tag alone. A value of a recursive type is a pointer to a node for each variant with a payload, which holds the payload's words, and an immediate for each variant without. A node, as every data object, is a header of two words, its count, kind, flags and tag, then a *layout word* that tells how many fields it has and which of them are heap words, a bit for each below a bit set at its length (`stilt_runtime::layout::data_layout`), then its fields, a word each (`stilt-runtime/src/object.rs`): an object of up to 30 fields takes its header and its fields alone, 256 bytes at most, a block of its thread's pool, and a larger one keeps its heap bits in a mask word per 64 fields after them, so the red-black tree's node of five fields takes 56 bytes. A test of a variant that a value of its type holds in an object, when every other variant of the type is an immediate, as `Node` of `Leaf | Node(..)` is, is a test of the word's lowest bit (`stilt-mir/src/lower/patterns.rs`). Generic code is compiled for the layouts of its type arguments, not for the types (`stilt-mir/src/lower/keys.rs`): a call names its callee's instance whose key gives, for each type parameter, the class of each word its argument is held in, a scalar, a heap word, or a word whose heapness the caller's own witness tells, and the code compiled once serves every argument held in one word, whose witness tells whether it is a heap word. So a generic function holds, passes and returns a value in the words that the code naming its type does, and each instance is a function of its own, which an edit of the generic function compiles again wherever it is in use (goal `edit-to-running-program`). Dictionaries stay one per bound, each method compiled for the layouts of its impl's type arguments; it takes a value of `Self` or of a type parameter in one word, lent in a box on its caller's stack if it has several, as the runtime passes values to the methods of `Eq`, `Ord`, `Hash` and `Show`, and an `inout` one of `Self` as a pointer to its words, which code that holds it in one word finds in its box, made unique, and gives one back in the words that hold it. A dictionary's method is compiled once for all the layouts of its own type parameters, so a type parameter bounded by a trait with methods of their own type parameters is keyed by its argument's constructor as well, and the instance calls the impl's method directly, compiled for those layouts. Keys have caps, so that generic code that calls itself with ever bigger types, which only polymorphic recursion does, has finitely many instances. They apply only to a request that an instance makes within its own cycle of the call graph (`stilt-mir/src/lower/keys/cycles.rs`), with a key bigger than any of the instance's own, so generic code that doesn't reach itself is compiled for its type arguments however large or deeply nested: there, a key knows at most 16 constructors, past which such a method goes through the dictionary, whose entry holds its own type parameters in one word, and a type argument that the instance builds from its own type parameters keeps at most 64 words inline. A call past the caps goes to code compiled for each type that would grow held in one word, its box, with its shape as its witness and dictionaries that forward to its own, and converts each value whose type holds one on the way in and back (`stilt-mir/src/lower/bridge.rs`): a composite field by field, a list or a map by rebuilding it, a value of a recursive type by rebuilding the nodes that hold one, and a closure by a closure that converts what it takes and gives. So every program runs. A list holds its elements inline (`stilt-mir/src/lower/lists.rs`): each the words of its type's layout, one after the other, or a scalar narrower than a word in its own width, a `bool`, an `i8` or a `u8` in a byte, an `i16` or a `u16` in two, and an `i32`, a `u32` or an `f32` in four, whatever the element's size. A map holds each key and value in its words, as its shapes say (`stilt-runtime/src/map.rs`). Each type has a *shape* (`stilt-mir/src/shape.rs`), one word that tells the size of its values as elements, which of their words are heap words, whether a narrow scalar extends its sign, and in its lowest bit whether the one word that holds a value where a type parameter stands is a heap word; the shape of a value of more than 48 words, more than its mask has room for, points to a description of its words that the runtime makes once. A list keeps its elements' shape, so the runtime copies, releases, slices and sorts a list without knowing its type, and a type parameter's witness is its argument's shape, which tells the heapness of each of its words that a key leaves to the witness. Code that names a list's element type, or whose instance knows its layout, reads and writes each word of an element at a fixed offset: `xs[i].f` reads one word, `let b = xs[i]` copies the element's words, and `xs[i].f = v` makes the list unique once and writes one word in place. Code compiled once, which holds an element in one word, reads and writes it through the runtime, which converts it by the list's shape. The structural impls of lists lend an element to the methods of `Eq`, `Ord`, `Hash` and `Show`, whose results can't hold it, in a box on the stack that no count frees, so that comparing, hashing and showing a list allocates nothing for its elements. The code of a closure, and the code that function values reach a function through, take and give every value in the words of its layout (`stilt-mir/src/synth/adapters.rs`), and raise an error of several words to memory that their caller provides, as a function does whose error comes through a row variable (`stilt-mir/src/lower/raises.rs`): a caller that knows the error's type, from the call's row or from the `catch` or the signature that pairs the row variable with it, provides the memory, and one that doesn't passes on its own caller's. Natives take a value of a type parameter in one word, lent in a box on the stack if it has several; one that gives a value of several words of a type parameter, or an `Option` of one, as `List.get` and `Map.remove` do, writes its words to memory that its caller passes, and so does one that raises an error of several words, as `fs.read` raises an `IoError`; and a closure given to a native is wrapped, if it takes or gives a value of several words, in code that takes and gives them in one word (`stilt-mir/src/lower/natives.rs`). A constant is kept in its words, computed where it is first used: the runtime lets one thread claim it and compute it while any other that uses it then waits, marks what its value reaches shared, since every thread may read it, and says it is computed by a store that releases the words, whose state each read of the constant loads with a load that acquires them (`stilt-runtime/src/constants.rs`). Compiling each generic function once per layout rather than once per type keeps the functions a patch compiles again to the layouts in use, and keeps values out of the heap: a debug build makes a box only past the caps of instances, which only polymorphic recursion reaches; `just bench` counts the boxes each benchmark makes (`inline-values`). A function returns its result's words, or its error's, then the raised flag, in registers when they fit, eight on aarch64 and two on x86-64, and otherwise through memory that its caller passes a pointer to; a native returns two words, so the natives that return an `Option` of a word, such as `List.pop`, `List.get`, `Map.get` and `str.find`, allocate nothing. Assigning to a field of an inline value writes its locals; a path that goes through an element of a list, a value of a map or a node of a recursive type, and an `inout` argument, keep the value's locals together in a stack slot and write through a pointer, making each object on the way unique. Its tests are in `stilt-cli/tests/layout/`.

## Value parameters

A value parameter ([generics.value-parameters](../../reference/07-types.md#generics.value-parameters)) is passed as a hidden argument in the place of a type parameter's witness, holding its value, so one instance serves every value, as one `add<p: u64>` serves every modulus (`stilt-mir/src/lower/values.rs`). One of type `i64` may give an array its size, which changes the layout of the values the code holds, so it keys the instance by its value as well, and every value of an `i64` parameter is a literal, a constant or another such parameter, so a program has finitely many. An `Array<T, n>` holds its `n` elements inline, each in the words that hold a `T` where a type parameter stands, one after the other, as a record holds its fields, and an array of no elements is one word that holds nothing, as `` is (`stilt-mir/src/lower/arrays.rs`): making, copying, reading and writing one allocate nothing ([generics.array-effects](../../reference/07-types.md#generics.array-effects)). An array of at most 16 words is held in a local per word, as a record is. A larger one is one local of the MIR (`stilt_mir::mir::Repr::Array`), which lives in a slot of the frame, so that making, copying, moving, passing, returning, comparing, hashing and showing it, and counting and releasing its strings and other heap words, are a copy of its words or a loop over its elements, and its code is the same at 64 elements as at 65,536 ([generics.large-arrays](../../reference/07-types.md#generics.large-arrays); `stilt-mir/src/lower/arrays/memory.rs`, `stilt-mir/src/synth/structural/arrays.rs`, `stilt-codegen-clif/src/arrays.rs`). Sixteen words are as many as x86-64's general registers and half of aarch64's, past which code that works on a value spills most of its words to the frame anyway, so holding it in memory costs its reads little, while a 4×4 matrix of `f64` stays in words. A record, a tuple, a variant's payload, an object, a list's element, a map's key or value and a closure's environment hold such an array's words inline, as they hold any other value's, and code reaches each word by its offset in words; a call passes the array as a pointer to its words, which the callee copies into its own slot, and a function returns it through memory its caller passes, or in registers if it fits. A list literal where an array is expected is its elements' words, a list pattern on one is matched as a tuple's, and `for` reads each element in turn. `a[i]` with an index that the program computes reaches the element through a pointer to the array's words in memory, the variable's own when the array is a place, once the index is checked against the size, out of which it panics with `bounds`; `a[i] = v`, `a[i] += 1` and `inout a[i]` write it there. `fill`, `from_list` and `map` compile inline, since the caller knows the array's size, and the structural impls compare, hash and show the elements in order, writing an array as a list is written. A function whose frame takes more than a page touches each of its pages as it starts, so that a frame past the end of the stack faults on the stack's guard, and the run ends as a stack overflow does, with status 134 ([program.exit-statuses](../../reference/04-programs.md#program.exit-statuses); `stilt-codegen-clif/src/compile.rs`), rather than reaching past the guard. The program's thread, and each thread that a task or a worker runs on, has a stack of 64 MiB, and the body of a handler that takes control and resumes runs on one of 16 MiB (`stilt-runtime/src/entry.rs`, `stilt-runtime/src/fiber.rs`): an array of 65,536 one-word elements takes 512 KiB of a frame, so a stack holds dozens of frames that each hold one, beside the 10,000 frames of ordinary functions that [program.recursion-depth](../../reference/04-programs.md#program.recursion-depth) asks for. Code that would hold an array past both 2²² words and the 65,536 elements that [generics.large-arrays](../../reference/07-types.md#generics.large-arrays) asks for ends the run as running out of memory does, which the rule allows. A staging annotation ([meta.staging-annotations](../../reference/16-meta.md#meta.staging-annotations)) is checked and then runs as the form it annotates, which the typed body holds without it, so a debug build runs the erased program ([meta.erasure](../../reference/16-meta.md#meta.erasure)). Their tests are in `stilt-cli/tests/arrays.rs` and `stilt-cli/tests/large_arrays.rs`.

## Polymorphic function values

A value of a polymorphic function type ([polymorphism.function-types](../../reference/07-types.md#polymorphism.function-types)) is a closure whose code takes, after the closure, a witness for each of the type's parameters and a dictionary for each of its bounds, then its arguments, and is compiled once, holding a value of each parameter in one word (`stilt-mir/src/lower/poly.rs`). Type checking gives each use of such a value its type arguments (`stilt_types::tast::ExprKind::Instantiate`), and checks a closure literal or a generic function given for one with the type's parameters as rigid types of their own, copies made for that argument. A call passes the witnesses and dictionaries of its type arguments, and an argument of several words in its box, converting what crosses as a call past the caps of instances does, and a closure of such a type that crosses the caps itself is held by one whose code takes the witnesses and dictionaries and passes them on; a generic function given for such a type is a closure whose code calls it at the rigid types, and a value used where a monomorphic function type is expected one whose code calls it at its instantiation. `std.lazy`'s `Lazy<T>` is a data object of the runtime (`stilt-runtime/src/std_lazy.rs`) that every copy shares: its closure until the first `get` runs it, then the value, in its box if it has several words. A thread counts the computations it runs, and a worker the ones whose call of `std.par` gave it its part, so that a `when` that runs meanwhile panics with `deadlock` (`stilt-runtime/src/tasks/order.rs`; [polymorphism.lazy-waits-for-nothing](../../reference/07-types.md#polymorphism.lazy-waits-for-nothing)), as E0435 checks of the function written at `Lazy.new` (`stilt-types/src/analyses/implicit/locks.rs`).

## Reflection

Reflection ([meta.static-reflection](../../reference/16-meta.md#meta.static-reflection)) is checked in `stilt-types`: `T.shape` and `T.name` resolve after a type's own members in a module that names `std.meta` (`stilt-types/src/infer/reflect.rs`); a shape's case binds fresh types, rigid types of its arm or loop body, whose values E0351 keeps inside it (`stilt-types/src/infer/fresh.rs`); and `reflects T`, an inferred fact that `stilt show` prints, is a fixed point over one summary of each body, from which E0350 is reported where a type without a shape is given (`stilt-types/src/reflects.rs`). A debug build passes a descriptor of each type a function reflects on, names or tests, after its witnesses and dictionaries (`stilt-mir/src/lower/meta.rs`): a data object of its case, name, witness, table of impls and the fields of its case, made by the code of a thunk that the compiler makes for the type's form, its type parameters numbered, from their own witnesses and descriptors (`FnRef::Describe`). The parts' descriptors are thunks, made when called, so a recursive type's descriptor is cyclic without holding itself; and the accessors that read or make values of the type are closures of code compiled for its layout (`FnRef::Access`), which take and give values in the one word that holds them where a type parameter stands, as the code that reflects holds a fresh type's. The accessors of `std.meta` compile inline, reading the descriptor (`stilt-mir/src/lower/meta/calls.rs`), but `n.parse`, a native of the runtime (`stilt-runtime/src/std_meta.rs`). A bound test reads the dictionary of each trait it names from the table, which holds the dictionary of every trait that the program's bound tests name, of the traits their impls bound their type parameters by, and of `Eq` and `Hash`, or 0, each with the identities of the arguments the impl gives the trait's parameters, which a test with arguments compares with its own; an impl whose own bounds a type argument doesn't meet has no dictionary there. It gives the branch it guards those dictionaries. What a call can't see travels with what it passes: a dictionary holds the descriptors of the impl's type parameters that its methods read, and of those its type and trait arguments hold where the trait's defaults read `Self` or the trait's parameters, built where the bound is met ([meta.types-without-shape](../../reference/16-meta.md#meta.types-without-shape) and [meta.unseen-instantiations](../../reference/16-meta.md#meta.unseen-instantiations); `stilt-mir/src/lower/dicts.rs`); and a trait method's own type parameter that an impl or the default reads, `Self` and a trait's parameter that a default reads pass their descriptors beside their witnesses (`stilt_types::reflects::carried`). An edit of a type changes the code of its descriptor, and no function that reflects on it (`stilt-mir/src/lower/meta/tests.rs`).

## Handlers

A handler ([handlers.handler-types](../../reference/12-effects.md#handlers.handler-types)) is a data object: its kind, then for each operation the hash of its name and a closure whose code takes the box of its arguments' words and gives its result in one word (`stilt-mir/src/lower/handlers.rs`). A `with` installs it in the runtime's list of handlers of the running stack, and removes it however its block ends: at its end, at a `return`, `break` or `continue` out of it, and at a raise, which a `catch` that the `with` puts around its block receives before passing it on (`stilt-runtime/src/effects.rs`). A performance calls a closure of the runtime, which finds the nearest handler of its effect and calls the operation with the handlers outside its `with`. A handler that resumes at once gives the performance its body's value. A body that takes control and ends without resuming ends its `with` with its value as an *abort*: the performance raises it, so every row that holds an effect can raise, as a row variable can, every `catch` passes an abort on, and the `with` whose handler it ends takes the value. A row that holds `async` can raise one too, which stops code that the sequential run never reaches, below. A body that resumes runs on a stack of its own, which the runtime maps with a guard page below it and switches to and back from, saving the registers that calls preserve (`stilt-runtime/src/fiber/native.rs`, for aarch64 and x86-64, telling the sanitizers of each switch; WebAssembly's below): `resume(v)` switches back to the performance, which gives `v`, and the body waits until the block ends, when the `with` gives its value to each body that waits, the latest first, whose own value replaces it. A `with` that its block leaves otherwise cancels the bodies that wait: their `resume` raises an abort, which unwinds them. Under `task.sequential`, or with no `with`, `std.task`'s natives run each task where `spawn` starts it, which is the program's meaning ([tasks.sequential-run](../../reference/14-tasks.md#tasks.sequential-run); `stilt-runtime/src/std_task.rs`). Under `task.threads`, which `spawn` finds as the innermost handler of `async` or the one its task runs under, `spawn` gives the task's function a deep copy of what it captures, which stops at the objects that threads share, a `Shared<T>`'s handle among them, and at a task's handle, which it marks shared with the task's value (`stilt-runtime/src/object/copy.rs`), and runs it on a thread of a pool, with the program's stack, so that a stack overflow there ends the program with status 134 (`stilt-runtime/src/tasks.rs`). The run's output is a tree of segments, one per task, inserted in the segment of the code that started it at its `spawn` (`stilt-runtime/src/tasks/segments.rs`): the first segment whose task hasn't ended writes out, the others keep what they write until every segment before them has ended, so stdout and stderr read as the sequential run writes them ([tasks.same-output-under-every-handler](../../reference/14-tasks.md#tasks.same-output-under-every-handler)). A read of stdin, a panic, an `exit`, running out of memory and a stack overflow's report wait until their segment is the first. `await` waits for the task, and a `with` of `task.threads` ends once every task started under it has ended ([tasks.with-waits](../../reference/14-tasks.md#tasks.with-waits)). A task started inside a `when`'s block runs where it starts, as the sequential run does, and so does one started past 512 running tasks. A task's thread takes on the watched run of the code that started it, so a task's panic ends a test, a property's case or an input of the REPL as the run's own thread does, and a thread of a watched run that wakes once the run has ended stops for good; `run` keeps the program's code while a task of an ended run hasn't. A scope's `s.spawn` runs its task where it starts too, so its raise is the call's, unless the scope runs on threads ([tasks.scope-failure](../../reference/14-tasks.md#tasks.scope-failure); `stilt-runtime/src/std_scope.rs`): under `task.threads` the scope's function runs on a thread, with a deep copy of what it captures as a task's function has, while its caller waits, and an `s.spawn` written in that function outside every `catch`, whose raise would leave the scope at once, starts its task on a thread, which compiled code tells it (`stilt-mir/src/lower/scopes.rs`). The function goes on as the sequential run does when the task doesn't raise; a task that raises cuts the function's segment after its own, cancelling the tasks after it and dropping what anything after that point writes, and its error is the scope's, unless a task before it raises too. Code past such a raise stops when it waits for a task that ended without a value, by an abort that unwinds it, starts no task, and stops for good, with what its frames hold, at a read, a `when`, a panic or an `exit`. Nothing waits for it: a cut or a cancel tells the scope, or the `with`, that waits for the task or the function at once, so a cancelled task that never ends keeps nothing waiting (`tasks::Waited`). While such code holds a thread, running or stopped, a debug build skips its check at exit that every count is back to zero, which can't tell what that thread holds from a leak. Their tests are the conformance suite's `handlers/` and `tasks/`.

## Shared values

A `Shared<T>` ([shared.std-sync](../../reference/14-tasks.md#shared.std-sync)) is a data object of its value's words, which every copy of the handle reaches and no write makes unique (`stilt-runtime/src/std_sync.rs`). A `when` tells the runtime each of its handles at its location, where it panics with `deadlock` if a `when` of the thread, or of the code it runs where it starts, holds the value ([shared.when-on-value-already-held](../../reference/14-tasks.md#shared.when-on-value-already-held)), then holds them all at once, and binds each of its names to a pointer to the words of the value its handle reaches, as an `inout` parameter is bound, so its block reads and writes the value in place, and two names whose handles reach one value are one place; it lets them go however its block ends, at its end, at a raise and at a jump, as a `with` removes its handler, marking what the block left in each value shared (`stilt-mir/src/lower/shared.rs`, `stilt-runtime/src/tasks/order.rs`). Under `task.threads` it first waits until no task before its point in the sequential order that hasn't ended holds handles, having captured a `Shared<T>` or a task's handle, or may raise, being a scope's, and until no other thread holds one of its values, so the blocks of one value run in the sequential order and none runs in code that a raise cancels ([shared.when-order](../../reference/14-tasks.md#shared.when-order)). The functions of `std.par` ([par.std-par](../../reference/14-tasks.md#par.std-par)) are natives that run in parts on the runtime's own pool of threads, one per core, the calling thread among them (`stilt-runtime/src/std_par.rs`, `stilt-runtime/src/workers.rs`): `map` and `each` split their list into up to four parts per thread, each part calling the closure from its first element to its last, `both` runs the first closure on the calling thread and the second on another, and `fold` folds the subtrees a few levels down the balanced tree that the list's length fixes, one per part, which the calling thread then combines as the tree says, so a float fold gives the bits of [par.fold-tree](../../reference/14-tasks.md#par.fold-tree) on any number of threads. A call over fewer than four elements, or on one core, runs on the calling thread. Before a call runs on several threads, the closures that other threads call are marked shared with what they capture, and so is what the list's elements reach through an object that something else references too, as `[a, a]` reaches `a`, so that the threads count those objects atomically; an object that one element alone reaches stays unmarked, and the list itself, which the threads don't count, too. `map` writes each result into its element of the new list, and `each` makes its list unique, then passes each element's words in place to its closure, which takes them `inout`. The calling thread runs the first part and finishes the others in order, waiting for those a worker took and running those none took, so a call inside a part, whose parts the workers take first, never waits for a busy pool. A worker whose part panics, runs out of memory or reaches a watched run's stop records how it ended and waits forever, another taking its place, and the calling thread, once every part before it has ended, ends the program the same way through the runtime's usual paths, so the program reports the first panic in [par.fold-tree](../../reference/14-tasks.md#par.fold-tree)'s order, as [par.panics](../../reference/14-tasks.md#par.panics) says, and a watched run, a test or a property ends as it does on one thread; a stopped run's stop also waits for the workers still running its parts to reach their next poll. Workers have the stack of the program's thread, and a stack overflow on one ends the program at once with status 134 ([program.exit-statuses](../../reference/04-programs.md#program.exit-statuses)). A `Lazy<T>` that threads share is computed once, by the first thread that claims it, while the others wait. Their tests are the conformance suite's `shared/` and `par/`, and the runtime's tests of `std.par` and its pool, on one, two, three and sixteen threads.

## Projections

A projection, a function whose result is written `inout T` ([projections.declaring-projection](../../reference/13-modes.md#projections.declaring-projection)), is lowered to a function that takes the caller's access as one more argument, after its parameters: a closure given a pointer to the yielded place, as Swift's `_modify` accessors and Hylo's subscripts are (`stilt-mir/src/lower/projections.rs`). `g.at(1, 0) = 5` calls `at` with a callback that stores `5`, a read calls it with one that copies the place's words out, through memory the caller provides, and nested projections nest their callbacks. A statement or a call whose places are rooted in projections' calls is lowered in two steps, as the interpreter prepares and opens a place: every expression of it is evaluated in its turn first, the projections' arguments and the index expressions among them, and recorded by its node, with a pointer to the root of each place of the function's own; then each projection is opened by a call with a callback whose code opens the next, the arguments of a projection before it and from left to right ([projections.when-projection-runs](../../reference/13-modes.md#projections.when-projection-runs)), and the last callback lowers the statement again, which finds its values recorded and each call opened as a pointer. A callback is a closure of the function, its environment the values recorded so far, and runs in the caller's frame as the access does: its raise goes to the caller as a closure's does, in one word or to memory the caller provides, past the projection, which raises it again without resuming and without its own `catch` arms seeing it ([projections.raising-during-access](../../reference/13-modes.md#projections.raising-during-access)); every projection takes that memory, as a function whose row holds a row variable does. At its `yield`, the projection takes a pointer to the place, as an `inout` argument is passed, calls the callback, and writes the place back when the callback returns or raises. A projection called through a dictionary passes the callback on from its entry, and one past the caps of instances isn't bridged: its instances follow its type arguments. A writable view, made by `view.into`, `view.part` or `view.split`, is held as any view is, its source's word with a reference of its own and two offsets, into storage that `into` and `split` have made unique first (`stilt-mir/src/lower/windows.rs`): the source and the view then share one object, so a view handed back in a result, or copied out of a yielded place, still points at the caller's storage, and a write through `v[i]` goes to that object's element without checking its count, since the law of exclusivity keeps every other access away while the view's binding lives ([projections.what-view-writes](../../reference/13-modes.md#projections.what-view-writes)). `split` calls its closure with pointers to the two views' words, and what the closure raises passes through. `stilt show` prints `writes` for a writable binding and for a result that writes an `inout` parameter, as it prints `views` (`stilt-ide/src/show/views.rs`).

## Running and patching

`stilt run` runs a program and patches each edit of its files into it while it runs, until the program ends, when `run` ends with its status (`stilt-cli/src/run.rs`). Its code comes from the program's engine when one runs, as above, and otherwise from a database of `run`'s own, lowered by the same code (`stilt-cli/src/run/code.rs`), so that `run` compiles and patches alike whatever gives it its code. The main thread looks at the files every 50 ms, as the engine does before each command, while the program writes its output a line at a time, as a built executable does ([program.output-flushing](../../reference/04-programs.md#program.output-flushing)); otherwise it waits on the program's thread, which wakes it as it ends, so a program that ends before the first look waits for none, and the image, with the database that `run` holds when no engine does, ends with the process. Every function is called through a slot that holds the address of its latest code, in calls, function values and dictionaries alike, so an edit compiles again only the functions whose MIR changed and stores their new addresses: the next call of an edited function runs its new code, and the program keeps its state. An edit that changes which parameters a function consumes changes how its callers pass them, so their MIR changes too and the patch compiles them again: the query database finds them. To find the functions an edit changed, `run` keeps the last walk of what the program's entry reaches (`stilt_mir::Walk`, `stilt_rc::Reach`): each function it reached, with the functions that make it up and the functions they name. After an edit, each function it reached is proved unchanged by the query that lowered it, across the machine's cores, and compared with its last code at no cost, since a query that didn't run again gives the same `Arc`; the steps of the walk are taken again only when the roots differ, or a function whose code changed names other functions, since only then can what is reached differ. Only the functions whose lowering ran again and those reached for the first time are counted and given, a function edited while unreached among the latter once it is reached again, unless what some function consumes changed, which changes its callers' code, and every function reached is counted again. What the functions reached consume follows only their own summaries, since a function passes its parameters only to the functions it calls directly, so an edit that leaves what is reached as it was, and the summary of each function whose lowering ran again, reads no other summary. A function's closures are lowered with it and named only by its code, so the walk never visits them on their own. On the 100K-line project, proving a body edit's front end and walk unchanged takes 9 ms, where walking every function again, its closures among them, took 39 ms. Each convention a function has had keeps a slot of its own, and the slots of the earlier ones hold a bridge to the latest code, which copies or releases what the two conventions disagree on, so that code already running in a caller's old frame reaches the new version too. An edit with errors patches nothing, and reports its diagnostics. An edit that changes the layout of the program's values, its types' or its traits' declarations, stops the run and starts it again; compiled code polls a stop flag on entering a function and on each loop's back edge so that a run can be stopped, the call that stops it laid out cold, so that the hot path pays a load and a branch not taken. The program runs on a thread whose end reports to `run` rather than ending the process, and a run checks at its end that every count is back to zero, patched or not, but for a run started again after one was stopped, which keeps the stopped run's objects. A program that had errors when it started ends with status 2 however it ends, even when an edit fixes them ([program.programs-with-errors](../../reference/04-programs.md#program.programs-with-errors)). Its tests are in `stilt-cli/tests/run.rs`, and those of the walk and of what it gives in `stilt-mir/src/walk/tests.rs` and `stilt-rc/src/reach/tests.rs`; `just latency` times each edit of the script on the 100K-line project until its new code is live (goal `edit-to-running-program`), splitting each update's time into validation, the update timed again after a revision that changed nothing, analysis, code generation and patching, and checks after each edit that the image holds, for every function the program reaches, the code that walking and counting the program afresh gives it (`incremental-equals-clean`).

## Builds and targets

`stilt build [--target T] [-o OUT] PATH` writes an executable for the target T, `aarch64-macos`, `x86_64-linux`, `aarch64-linux` or `wasm32-wasip1`, or for the host, from either host (goals `targets` and `cross-compilation`), WebAssembly's as below. The program's object file, from Cranelift, is linked with the target's runtime library by LLVM's linker, `rust-lld`, which needs nothing of the target's system: an x86-64 Linux executable is static, linked with musl, and an aarch64 macOS executable links the system's `libSystem` through a stub that lists the symbols it takes from it, so no macOS SDK is needed. The linker and the libraries are the toolchain, `stilt-toolchain` beside the `stilt` executable or the directory `STILT_TOOLCHAIN` names; `just toolchain` assembles it in `target/`, with each target's runtime built optimized by the Rust toolchain that `rust-toolchain.toml` pins, the macOS library without the DWARF of Rust's standard library, which debugging a program never reads and `dsymutil` would gather at every build, a third of a small program's build, and `just build` runs it. The executable runs the program as `stilt run` does, and checks at exit that every count is back to zero. `just run` runs the conformance suite through built executables for the host, by way of `tools/runner/built.sh`, and `just latency` times a clean build of the 100K-line project (goal `clean-debug-build`). An engine keeps, from one build to the next, the reference counting of each function the build reached and its machine code, with its relocations and its DWARF (`stilt-codegen-clif/src/reuse.rs`, `stilt_cli::build::Kept`), so that a build after an edit counts and compiles with Cranelift only the functions whose counted MIR the edit changed, and defines every other from the code kept of it (goal `compile-time-code-rebuilds`). The code follows the function's MIR, the target, the settings every build shares, and what its translation asked of the module's registry: the static data and the imports it declared, whether each callee is compiled, the slots it calls through, and for the entry, the constants it releases. A build asks these again for each function it keeps, in the order of the functions, which declares everything as translating it does, keeps the code when every answer is the one its translation had, and relocates the code and its DWARF against the numbers the answers give: an edit that adds a function or a constant before others moves their numbers in the module, and their code is reused all the same. So the object and the executable are those a clean build writes, byte for byte, whatever was kept. A build for another target than the last starts afresh, and the code kept of a function that a build no longer reaches goes once that build ends (`bounded-cache`). On the compile-time benchmark, a build after no change takes about 0.10 s through an engine, where it took 0.23 s, and its baseline 0.09 s, where it took 0.16 s. `just cross` runs the suite across the matrix of hosts and targets on an aarch64 Mac, by way of `tools/runner/cross.sh`: Docker emulates the x86-64 Linux host and target, the Mac builds for Linux, and the compiler built for Linux builds for both targets, each executable running on its target. Its tests are in `stilt-cli/tests/build.rs`, among them builds after edits, each the same byte for byte as a clean build, and those of the code kept in `stilt-codegen-clif/src/reuse/tests.rs`.

## Release builds

`stilt build --release` writes the program's release build ([builds.release-builds](../../reference/20-builds.md#builds.release-builds); `stilt-cli/src/release.rs`): the same counted MIR that a debug build compiles, by way of the engine as a debug build does, written as freestanding C11 by `stilt-codegen-c`, a file for each module and `program.c` for the code that no module holds, with the C `main`, and compiled by clang across the machine's cores, the largest file first, at `-O2`, with no link-time optimization. A function that no other file names is `static`, so clang inlines it and drops what it no longer calls. A call whose result the function returns at once, moved but unchanged, of a callee that can't raise, returns what the callee returns, so that clang makes a call of the function itself a jump, as the queens' `safe` of the Perceus paper's nqueens is a loop (`stilt-codegen-c/src/calls.rs`). The runtime's fast paths are `stilt.h`, a header that each file includes after the constants of the runtime's layout, written from `stilt_runtime::layout` and checked by `_Static_assert`, so that a header out of step with the runtime fails to compile. A list's length and the address of its elements stay in C locals while nothing can change them (`stilt-codegen-c/src/lists.rs`), a forward analysis over each function's blocks that a store to the list's place, an append to another list or a call gives up, so that a loop that writes a list's elements reads its header once. The list an `inout` parameter points to is such a place too, the caller's slot, which nothing else reaches while the call runs ([modes.overlapping-inout](../../reference/13-modes.md#modes.overlapping-inout)), so a function that writes the elements of a list it takes `inout`, as n-body's `advance` does, reads the list's header once rather than at each element. A release build drops the checks that the analysis or a rule of acceptance proves can't fail ([builds.dropped-checks](../../reference/20-builds.md#builds.dropped-checks)): lowering marks the location word of each such operation in its two highest bits, which no file's index reaches (`stilt-mir/src/lower/proved.rs`), a proved read or slot of a list's element is written as the form that checks nothing, and a proved check of a number or of an array's index as a condition that clang takes as false, so it drops the test (`stilt-codegen-c/src/proved.rs`). A debug build reads no mark, and the runtime reads a location without them. A proved key of a map keeps its check, which is the runtime's test of its lookup's result, and so does an index into a list of a type parameter's values, which the runtime reads. Each object is kept in the user's cache, `objects/` in `STILT_HOME`, under the BLAKE3 hash of its C, the clang and the flags, so that a build after an edit compiles only the files of the modules it changed, and an object unused for a week goes at the first build of a day (`release/objects.rs`). The objects link as a debug build's object does, with `rust-lld` and the target's runtime, and the executable is the same bytes from any directory and any cache, its line tables in the executable on Linux and gathered into `OUT.dSYM` on macOS. The clang is the one `STILT_CC` names, or `clang/bin/clang` in the toolchain, which `just toolchain` links to the build machine's clang once its version is the one `stilt` names, or the archive that `release/toolchains.txt` names for the host, fetched once into `STILT_HOME/toolchains/` and checked against its SHA-256 (`release/compiler.rs`, `stilt-pkg/src/toolchain.rs`); no archive is published yet, which is a step of a release. A release build refuses a program with a hole, as with an error, with status 2. `STILT_C_DIR` keeps a build's C in a directory. Its tests are in `stilt-cli/tests/release.rs`, `just run` builds the conformance suite's run tests as release builds too, by way of `tools/runner/release.sh`, `just cross` builds the Mac's release builds for Linux, `just differential` runs a sample of generated programs as release builds, and `just bench` measures them against their Rust baselines (`release-speed` and `no-outliers`).

## Specialization

A release build specializes ([builds.specialization](../../reference/20-builds.md#builds.specialization); `stilt-mir/src/special.rs`). A debug build's generic function takes, after its location, a witness and a dictionary for each type parameter, its value parameters and the descriptors of the types it reflects on, its hidden parameters (`Function::hidden`). From the roots, `main`'s entry for an executable, each call whose hidden arguments are known calls an instantiation made from the callee's counted MIR with them in place (`special/function.rs`, `special/known.rs`): a dictionary's methods called directly, a value parameter folded into the arithmetic, a descriptor's parts read where they are written, and each branch they decide made a jump; a dictionary's method and a closure are compiled for the object that holds them. Instantiations whose code is the same are one function (`special/merge.rs`), and a build makes at most four times the debug build's functions and 1,024 more, and 4,096 of one function. The functions of a recursive group in which a call passes a type argument built from the group's parameters without being one keep their dictionaries ([builds.what-stays-generic](../../reference/20-builds.md#builds.what-stays-generic); `special/groups.rs`), and so do calls of a polymorphic argument, whose callee no call knows. On the 100K-line generated project, specialization turns 706 functions into 960 and 143 indirect calls into 32, and the C shrinks from 5.1 MB to 4.8 MB.

## Profiles

`stilt run --profile` and `stilt test --profile` hold the program in their own process, with no engine and no patching, and lower it with marks of what a profile counts (`stilt-mir/src/profiling.rs`): each body's entry, at its name, each arm of an `if` or a `match`, each loop's body, and each call that reaches a dictionary's method or a function used as a value, counted by the adapter it enters with its caller's location. The marks call the runtime's counters (`stilt-runtime/src/profile.rs`), and at the end of a run whose status isn't 134 the counts go into the program's profile, `NAME.profile` beside a file `NAME.lt` and `default.profile` in a directory, each place relative to its body's start, added to the counts there and rounded down to a power of two, in sorted lines (`stilt-cli/src/profile.rs`). A line not of the form is E0610, which `check` reports and a release build and a profiled run refuse. A release build of a program with a profile holds the program in its own process, marks the same places with no counter, and gives clang, from each line whose body's hash is current, the probability of each branch between two counted arms, of each test of a `match` against the arms tested after it, or into a loop's body, `__builtin_expect_with_probability`, and `hot` or `cold` for each function whose body was entered at least a sixteenth as often as the most entered or never (`stilt-codegen-c/src/hints.rs`), so a profile changes no code but those hints. `stilt show --release ADDRESS [PATH]` builds the release code in its own process and reports each function's costs ([builds.performance-report](../../reference/20-builds.md#builds.performance-report); `stilt-cli/src/show/release.rs`): the lists of arguments the roots reach it at, from the typed bodies (`stilt-mir/src/special/types.rs`), each call left on a dictionary and why, the reference-count operations and copies of the code compiled for it, by line, the checks that verification proves and those it doesn't, and the lines of the profile at its body that the build drops. `tests/costs/` checks it, its reference counts pinned by reviewed snapshots (`stilt-cli/tests/costs.rs`), and `just run` builds every run test of the conformance directories whose code specializes as a release build.

## WebAssembly

`stilt build --target wasm32-wasip1` writes a WebAssembly module, `NAME.wasm`, a WASI preview 1 command that imports only WASI's functions ([wasm.target](../../reference/20-builds.md#wasm.target); `stilt-cli/src/wasm.rs`). Cranelift writes no WebAssembly, so both of its builds go through the C back end: a release build as above, and one without `--release` that keeps every check, and the program's holes, which run as a debug build runs them ([wasm.target](../../reference/20-builds.md#wasm.target)); `--lib` is an error that names the target. clang compiles the C for `wasm32-wasip1`, where `stilt.h` checks the stack pointer at each function's entry against the end of the module's stack, less a margin for the runtime's own frames, so that an overflow reports `fatal: stack overflow` and traps. A word stays 64 bits wide, an address held in one, and the runtime's functions take addresses as `u64`, so one C declaration fits every target. `rust-lld`, as `wasm-ld`, links WASI's start file, the objects, the runtime's library built for `wasm32-wasip1`, wasi-libc and clang's builtins, with the module's 8 MiB stack first in memory, so that running past it traps, and its memory at most 4 GiB ([wasm.limits](../../reference/20-builds.md#wasm.limits)); `just toolchain` fetches wasi-libc and the builtins from wasi-sdk's archives, binaryen and wasmtime, each the archive that `release/wasm.txt` pins, checked against its SHA-256, into `target/wasm-tools/`. On this target the runtime runs `main` on the module's one thread, `task.threads()` runs its tasks as `task.sequential()` does and `std.par` its closures in order ([wasm.tasks-in-order](../../reference/20-builds.md#wasm.tasks-in-order)), `random.entropy()` reads WASI's `random_get`, `io.poll_line` polls through `poll_oneoff`, and a path that no directory the runtime granted holds raises `PermissionDenied` ([wasm.what-std-reads](../../reference/20-builds.md#wasm.what-std-reads); `stilt-runtime/src/wasm.rs`). A status of 134 ends the module by a trap, since WASI's `proc_exit` takes no status above 125 ([wasm.exit-statuses](../../reference/20-builds.md#wasm.exit-statuses)). A body that resumes runs on a stack of its own (`stilt-runtime/src/fiber/wasm.rs`): its C stack is memory that the runtime takes, 1 MiB, and binaryen's Asyncify, which `wasm-opt` applies once the linked module imports it, unwinds the frames from the body to the switch into memory and rewinds them back. It instruments only those frames, the compiled bodies that call `resume` and the runtime's switches, so no other function pays for it ([wasm.handlers-that-resume](../../reference/20-builds.md#wasm.handlers-that-resume)): in a module of 80 KB of code whose handler resumes, the handler's body and four functions of the runtime grow, the code by 3%, where instrumenting every function that could unwind makes it 3.6 times as large. Its tests are in `stilt-cli/tests/wasm.rs`, which run modules under the pinned wasmtime: the natives of [wasm.what-std-reads](../../reference/20-builds.md#wasm.what-std-reads), the limits of [wasm.limits](../../reference/20-builds.md#wasm.limits) and the builds of [wasm.target](../../reference/20-builds.md#wasm.target). `just cross` runs the conformance suite's run tests as release builds for WebAssembly under wasmtime, with the stack, the directories and the environment of [wasm.conformance-runs](../../reference/20-builds.md#wasm.conformance-runs), a cell that needs no Docker, which `just cross wasm` runs alone.

## Foreign functions

A foreign function ([c.foreign-functions](../../reference/20-builds.md#c.foreign-functions)) is called through `FnRef::Foreign`, which holds its C symbol and the C types of its parameters and result (`stilt-mir/src/lower/foreign.rs`): the back ends pass each argument's word as C takes its type, and take the result back into a word (`stilt-codegen-clif/src/foreign.rs`, `stilt-codegen-c/src/foreign.rs`). In memory, and in an executable for aarch64 macOS, a call takes the function's address from the runtime, which looks its name up at its first call among the C library and the libraries that the program loaded, and keeps it (`stilt-runtime/src/c_libraries.rs`); `main`'s entry, a test's and a property's load the libraries of the program's packages before anything else, in the order of [c.loading-libraries](../../reference/20-builds.md#c.loading-libraries) (`stilt-mir/src/synth.rs`). An executable for x86-64 Linux or WebAssembly links each foreign function by its symbol from the target's C library, musl's or wasi-libc's, and a program whose packages link a library builds for neither ([c.build-targets](../../reference/20-builds.md#c.build-targets), E0612). `with_ptr`, `with_mut_ptr` and `with_c_str` lend a list's elements or a copy of a string that a NUL ends to a closure, and the natives of `std.c` read and write through addresses (`stilt-runtime/src/std_c.rs`). `stilt-cli/tests/foreign.rs` builds a program that links zlib, as a debug and a release build, and one that calls `strlen` under wasmtime.

## Debuggers

Debug builds can be debugged with lldb and gdb, JIT code included (goal `debuggable-builds`). Lowering marks each statement's code with its source location (`Stmt::At`), and gives each local the source names a type to be shown by. `stilt-codegen-clif` turns the locations into DWARF line tables, and the locations Cranelift reports for each named local's values into location lists, with a constant's value where Cranelift keeps none, and for a local that holds an `f64`, both its float register and the word its bits are copied to, which a debugger reads by their DWARF numbers; the frame pointers are kept, and `.debug_frame` holds each function's call frame. Each function's DWARF is written once, when it is compiled, and kept with its code (`stilt-codegen-clif/src/debug/piece.rs`): its subprogram and locals, under abbreviations that one table declares for the whole unit, its location lists, each of which starts with a base address entry so that its ranges are offsets in the function's code, its sequence of the line table and its call frame. A build puts the pieces of its functions side by side in one compile unit (`debug/assemble.rs`), writing only what spans them, the unit's header, the line table's list of files, the types the locals are shown by and the unit's ranges, and fills in what each piece leaves open: the function's address, those of the data its constants point to, and the offsets of its types and its lists. A Mach-O relocation against a section holds the address in the object of what it points to, which only writing the object lays out, so each address is written as its offset in its section, and the section's address is added once the object is written, from its headers (`debug/sections/placing.rs`), rather than laying the object out twice. On the compile-time benchmark this takes a build 0.7 ms where writing the DWARF took 8.1. A Linux executable holds its DWARF; a macOS executable's DWARF, which Mach-O's linker leaves in the object, is gathered into `OUT.dSYM` beside the executable by `dsymutil`, which Xcode's command-line tools install with lldb, and the object goes. The JIT writes each load's DWARF into an ELF file in memory, given to debuggers through the GDB JIT interface, which gdb reads and lldb too with `settings set plugin.jit-loader.gdb.enable on`. An integer, a float or a `bool` shows as its value, each word of a value held inline as a local of its own, named `p.x` for a record's field, `t.0` for a tuple's element, and for a variant type, its tag under the value's name, shown as the variant's name, then its payload's words as `o.0`, `o.1` and so on, an array held in memory as a DWARF array at its slot's place in the frame, each element shown by its words, under their parts' names when it has several ([generics.large-arrays](../../reference/07-types.md#generics.large-arrays)), and any other value as a pointer to its object, whose header and, for a string, bytes a debugger can show; a string of at most seven bytes that the program made rather than wrote as a literal is held in its word, which a debugger shows as the word itself, its lowest byte twice the string's length plus one and its next bytes the string's. A local whose value reaches it through a block parameter, as when a release of a call's argument branches between the call and the local, gets its locations from the values that flow into the parameter, since Cranelift reports none for a parameter's label. `stilt-cli/tests/debugger.rs` stops at lines of a program, built and in memory, and checks what lldb shows on macOS, and gdb on Linux, where `just debuggers` runs it in Docker, an x86-64 executable among them under QEMU.

## Optimizations

Debug builds keep cheap optimizations, none of which crosses a user function's boundary in a running program, so each function can still be patched alone (goals `debug-speed` and `edit-to-running-program`); `stilt build` alone also inlines small user functions, as below. `stilt-mir`'s optimizer (`stilt-mir/src/opt.rs`) rewrites each function's MIR before its reference counting. First, a function of the program's own files inlines each call of a small function of the standard library written in Stilt that it gives a closure it makes, and the body's calls of that closure (`stilt-mir/src/opt/inline.rs`, the query `inlined`), as [Values and costs](values-and-costs.md) plans: the standard library never changes while a program runs, and a function's closures are lowered with it, so its code still follows its own MIR alone, and an edit compiles again only the functions it changes. A generic function is inlined only where the call gives each of its witnesses a constant, as code that names its types does, and its instance for the layouts of the call's type arguments then reads and appends its lists' elements as that code does, word by word. The body reads the call's arguments in place of its parameters, its location among them, so the standard library's code reports a panic at the call, as it does when it is called ([program.panic-location](../../reference/04-programs.md#program.panic-location)); it returns into the call's locals and raises by the call's raised edge, and its code is marked with the call's location for a debugger's line table, its locals unnamed, while a closure's code keeps its own lines and names. Scalar replacement then replaces each object that the function makes and only reads field by field by the words it reads (`stilt-mir/src/opt/boxes.rs`), as the closure itself once its call is inlined, and a closure whose every call is inlined isn't compiled. Inlining comes before the conventions of consumption are applied and before counting, so counting sees the inlined code, while what a function consumes still follows its own body. `stilt build`, which has no edit to patch, then inlines each direct call of a small user function (`stilt-mir/src/opt/inline/user.rs`, `stilt_mir::inline_calls`, run by `Counted::insert_built`): a function of the program's own files of at most 24 statements and blocks that isn't recursive, makes no closure, takes no `inout` parameter and has no type parameter, in two levels, so that `a(i, j)` of spectral-norm's loop costs no call and the range facts see its arguments (it runs in 0.56 times the time), and a function that nothing then calls isn't compiled; what each function names, by which a build finds what the entry still reaches, is kept from one build to the next by the function it was found in (`stilt_mir::Named`, kept in `Counted`), so that a build finds it again only in the functions an edit changed. The body keeps its own locations, so a panic in it reports the line it panics at, and a debugger's line table puts its code on its own lines, showing its locals in the caller's frame; the call's panics are the same under `stilt run`, which keeps the call (`stilt-cli/tests/inlining.rs`). Built and running code differ in speed alone. A call given no closure to the standard library stays a call, since inlining it gains the benchmark suite nothing and costs a build its code: the pipeline of closures over records runs in 0.96 times its baseline's time, where it took 2.04, and a clean build of the 100K-line project takes 0.1 s longer. An operation that repeats one of its block on operands that haven't changed copies that one's result, so `(i + j) * (i + j + 1)` adds and checks `i + j` once, the branches of `&&` and `||` test their condition once, and `if c { x += 1 }` steps `x` by `c`, which is 0 or 1, without the branch, which a predictor guesses badly where `c` follows the data, the step keeping its check and its location. Then range facts, which flow through the function alone, remove each check they prove can't fail: the bounds check of `xs[i]`, read or written, where `i` lies in `[0, xs.len)`, as the counter of `for i in 0..xs.len` or of `while i < xs.len` with `i += 1` does, or where `xs[i]` was read or written before without a panic, while nothing can change the list's length; the overflow check of `i + 1` where `i` is below another integer, as an index in bounds is; the checks of a division by a divisor above 0, as a loop's bound is inside it; and the overflow check of an addition, a subtraction or a multiplication whose operands lie between constants that keep the result in `i64`, a term's bounds following from the relations to constants that branches state, one step through another term, as a counter below a size that a branch bounded is, and from the bounds of what computed it, so that a grid's index `y * n + x` checks nothing once its program tests that `n` is at most 32,768. An operation whose operands are both known exactly keeps its check, which the back end folds with it, since a debug build's line table keeps an operation's line only while its check is there. A copy and its source are known equal while neither changes, so an index read through one copy is in bounds through another, and a branch whose condition the facts decide becomes a jump, as the test that ends each iteration of `for i in a..b` does. An addition of two integers known at least 0 keeps its check, which tests the sign of the sum, one instruction that branches, since only such an addition's overflow sets it. A list's length can't change while a local holds the list, since every change makes its object unique first, save a list that lowering builds for a literal or an interpolation, which nothing else references while it grows, so that building it leaves every other length known; and what a place holds changes only through a store to it, an element appended to it or a call given a pointer to it ([modes.overlapping-inout](../../reference/13-modes.md#modes.overlapping-inout)). A write reaches the list that its place holds, a variable or what an `inout` parameter points to, and a write in bounds still makes that list unique; the list of `xs[i][j] = v` that `j` indexes is held by an element, of which no fact tells, so its check stays. Once `stilt-rc` has inserted the counting, where every new reference to an object is a copy statement, each list is made unique once (`stilt-mir/src/opt/unique.rs`), as [Values and costs](values-and-costs.md) says an `inout` access through a list's element does: a write after another to the list a place holds checks nothing of the list's count while nothing between them can share it, which a copy of the list, or a call or a runtime function given it, might, and a loop that writes it in every iteration, and in which nothing can, makes it unique in the block that enters the loop, so that its writes check nothing, and a shared list is copied once, before the loop, rather than by its first write. A new list that a variable takes, as `var xs = []` or a list literal gives one, is unique there, since nothing else can reference it, and so is a unique list after `xs.pop`, which shares nothing of it (`stilt-mir/src/opt/unique/fresh.rs`). A release build then appends to and pops from such a list where it is, checking nothing of its count, so that its C keeps the list's length and elements in locals (`stilt_mir::opt::in_place`, which marks such a pop's location with `UNIQUE_LIST`): the stack of `bench/programs/vm` pops in 7% less time; a debug build appends through the list's slot, whose check costs Cranelift's code nothing it measures, and which runs nsieve's loop that fills its list in 17 ms where an append in place took 22. Every check that can fail is kept, and panics as before. `stilt-rc` lets a local that only reads a copy, a field or an element within its block, the block's terminator included, borrow it, uncounted, while nothing between its definition and its last use can release or change what it reads; a call can't unless it takes a pointer, the only way to the caller's locals, since closures capture by copy ([expressions.capture](../../reference/08-expressions.md#expressions.capture)), so `xs.len` on an `inout` list counts nothing. A local that a `let` binds once to a value that lasts the whole call borrows it for as long as it lives: a parameter that the function borrows, as a `for` loop over one reads it, and a field or an element of such a value, as a `match` on `xs[i]` reads it with what its patterns bind. `stilt-codegen-clif` compiles inline the fast paths of counting, of reading a list's elements, of appending one and popping one, of taking an element's slot for a write, its bounds checked or proved and its list made unique or proved unique, and of making an object unique before a write, with each slow path laid out cold. A block that raises releases each word by a call to the runtime instead, since a function takes it only on its failure, and the blocks of the fast paths it would multiply are most of what the register allocator covers in a function that releases many words on its way out: the instance of `json.read` for the 56 words of the compile-time benchmark's summary has 1,724 blocks rather than 2,994, and compiles in about 9 ms rather than 12. A failed check, such as an overflow, a division by zero or an index out of bounds, and a panic the program writes, branch to a cold block that calls a runtime function that never returns, then traps, so no value of the hot path has to survive that call and the register allocator keeps them in registers. Adding a constant to an integer, or subtracting one, checks for an overflow by comparing the integer with a bound, which Cranelift fuses with its branch, where an overflow flag takes it three instructions; a division by a constant other than 0 and -1 checks nothing, and a division by a variable tests for -1, and only then, in a cold block, for the least value. Stack slots take multiples of 16 bytes, so that the 16-byte spills of float registers that follow them stay aligned: a spill that crossed a cache line would stall each reload in a loop. A local that holds an `f64`, which the back end infers from the operations on it, since the MIR gives a local no type, is a float variable, kept in a float register; it is moved to a word, by a bitcast that keeps its bits, only where a call or a parameter passes it as one, memory takes it by float loads and stores, and the runtime's float functions take it in a float register. `stilt build` compiles at Cranelift's `speed` level. `stilt-runtime` keeps freed small blocks in a per-thread cache in front of the system's allocator, up to millions of each size (`stilt-runtime/src/pool.rs`). The thread that runs a program's entry owns one pool that compiled code reaches without a call, after comparing the thread's pointer, read from its register, with the pool's owner (`stilt-runtime/src/pool/owner.rs`), so a release build allocates a small data object and gives back memory that nothing built in with a few loads and stores, inline (`lt_alloc`, `lt_free`), and the runtime's own allocations look no thread-local variable up, which on macOS is a call; every other thread has a pool of its own, which only the runtime reaches. Releasing the last reference to an object frees it and every object only it reached through the pool, which it reaches once, in a loop that reads a small data object's heap words from its layout word, and an object none of whose children dies with it takes no worklist; no `memset` or `memmove` writes the masks of a small object or a list's last element; it holds a string of at most seven bytes in its word, an immediate whose lowest byte is twice its length plus one and whose next bytes are its own (`stilt-runtime/src/text.rs`), so that slicing, splitting and interpolating short text make no object, while a literal stays an object of static data whatever its length, and strings compare, hash and order by their bytes, a constant pattern's literal among them. A JSON parser's keys and short pieces then cost no allocation: at its long size json retires 1.02 times its Rust baseline's instructions where it retired 1.17, and string_heavy, whose millions of words are short, 0.51 times where it retired 0.98, its peak memory 700 MB where it was 1,744 (its baseline's is 1,189). The runtime builds as one codegen unit, so that its fast paths are inlined however its modules are partitioned. `List.sorted_by` and `List.sorted_desc_by` merge through one buffer that they take for the whole sort and sort short runs by insertion, and when the keys' dictionary is that of the structural `Ord` of an integer type, whose tag says so, signed or not (`stilt-mir/src/lower/dicts.rs`), they compare the keys as integers themselves, without a call per comparison. An object that threads share is marked so in its header, with every object it reaches, before a second thread can reach it (`stilt-runtime/src/object/share.rs`): its count then changes by atomic instructions alone, and a write copies it rather than change it in place, so whatever a marked object reaches stays marked, a mark is never removed, and marking stops at a mark ([Values and costs](values-and-costs.md), "Counts that are atomic only when shared"; goal `atomic-counts-where-shared`). Every other count changes by plain loads and stores: the inline fast paths load the word that holds the count and the flags once and test the bit, one `tbnz` on aarch64 and a `bt` and a branch on x86-64, and leave a marked object to the runtime, laid out cold. A `Shared<T>` is marked when it is made, and what a `when` leaves in it when the block ends. Only through a handle can objects reach one another in a cycle, which no count frees, so the shared objects that may be in one are collected by trial deletion (`stilt-runtime/src/object/cycles.rs`; [cycles.through-shared-values](../../reference/14-tasks.md#cycles.through-shared-values) and [cycles.freeing](../../reference/14-tasks.md#cycles.freeing)): once a shared value holds a handle or a task's handle, a release that leaves a shared object referenced makes it a candidate, which its header's last word places in a table, and when `Shared.new` makes a handle, a `when` lets one go, an allocation finds the heap full or the program ends, while no other thread runs the program's code, a collection lowers the counts of what the candidates reach by the references among them and frees what stays at zero, never looking into a value that a `when` holds. A debug build checks its counts at its end, and a release build doesn't, which C's `main` tells `stilt_rt_start`. Each thread keeps its own counts of the objects and bytes it allocates and frees, with its cache, and adds them to the program's totals when its entry returns, so no allocation contends for an atomic counter, a block freed on another thread joins that thread's cache, and the check that every count is back to zero stays exact. `just bench` measures the result on the benchmark suite of `bench/`, the tests of borrowing are in `stilt-cli/tests/counting.rs`, those of the optimizer in `stilt-mir/src/opt/tests.rs` and its modules, among them checks that can fail and are kept, those of inlining, whose panics are reported where they were, in `stilt-cli/tests/inlining.rs`, those of writes whose check is kept, which panic as before, in `stilt-cli/tests/checks.rs`, those of lists made unique once in `stilt-cli/tests/unique.rs`, of arithmetic whose checks are proved needless or made cheaper in `stilt-cli/tests/arithmetic.rs`, of sorting in `stilt-cli/tests/sort.rs`, and those of the float registers, the cold paths and the cheaper checks in `stilt-codegen-clif`.

How much memory a program may use is up to the implementation, which documents it ([program.exit-statuses](../../reference/04-programs.md#program.exit-statuses)). A program that the compiler runs, in memory under `stilt run` and `stilt test` or as an executable, may hold as much heap as the machine has memory, or the size that `STILT_HEAP` names, a number of bytes that `K`, `M` or `G` may follow for KiB, MiB or GiB, which the runtime reads when the program first allocates (`stilt-runtime/src/pool.rs`); the reference interpreter's heap is 512 MiB, and the tests of cycles set the compiler's to that size (`stilt-cli/tests/cycles.rs`). Every thread that runs the program's code, its own, a task's and a worker of `std.par`, has a stack of 1 GiB, which the system reserves and gives memory only as calls reach it, so a recursion a million calls deep runs, and a thread that stays shallow costs what it would with a small stack (`stilt-runtime/src/entry.rs`; [program.recursion-depth](../../reference/04-programs.md#program.recursion-depth)). A WebAssembly module has the limits of [wasm.limits](../../reference/20-builds.md#wasm.limits) instead.

Setting `STILT_DUMP_MIR` makes `stilt run` write the MIR of every function it compiles before the program starts, with its reference counting, to standard error.

## Unsafe code and the sanitizers

Only `stilt-runtime` and `stilt-codegen-clif` use `unsafe` (goal `visible-unsafe`): every other crate takes the workspace's lints, which forbid it, and clippy requires a `SAFETY:` comment on each block of the two. `just lint` checks both, and prints the count of blocks. `just sanitizers` builds the compiler, and with it the runtime, with AddressSanitizer and LeakSanitizer, on Linux in Docker from `tools/linux/`, and runs the conformance suite's run tests under it (`no-memory-errors`); the runtime's pool of freed blocks is off in that build, so that the sanitizers see every block freed and taken again. `STILT_SANITIZER=thread just sanitizers` builds it with ThreadSanitizer instead, the standard library rebuilt instrumented with it, and runs the run tests of tasks, threads, `std.par` and shared values under it, nightly; each handler's stack is a fiber the sanitizer is told of at each switch (`stilt-runtime/src/fiber/tsan.rs`), and the first race ends a run with its report.
