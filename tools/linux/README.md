# The Linux machine

The Linux machine that `just sanitizers` and `just debuggers` run in Docker, which runs Linux for the host's architecture, so on an aarch64 Mac it runs natively. [`machine.sh`](machine.sh) starts it: a container of the image that [`Dockerfile`](Dockerfile) builds, which mounts the repository at its own path and may trace processes. The image holds Rust at the version that `rust-toolchain.toml` pins, a pinned nightly whose rustc builds the compiler and its runtime with AddressSanitizer, which brings LeakSanitizer with it on Linux, LLVM's symbolizer, which names the functions in a sanitizer's report, gdb, and QEMU's user-mode emulation of x86-64.

- **Sanitizers** (goal `no-memory-errors`). `just sanitizers` builds the sanitized compiler in `target/sanitize/` with `--cfg stilt_sanitizers`, which turns off the runtime's pool of freed blocks and gives the sanitizers their options, and a plain build in `target/linux/`. It runs the conformance suite's run tests under the sanitized compiler, or with paths, the programs under them, each compared with the plain build's run.
- **Debuggers** (goal `debuggable-builds`). `just debuggers` runs `stilt-cli/tests/debugger.rs` with gdb: on a program that the compiler built for Linux runs in memory, and under QEMU's emulation, on one it builds for x86-64 Linux, with the machine's linker and the runtime libraries of `just toolchain`. The host builds the compiler and the tests for the Linux of its own architecture, static with musl, in `target/linux-musl/`, through [`musl.sh`](musl.sh), which `just cross` uses for x86-64 Linux too; the machine only runs them, since a build inside it reads every source through the mount. On macOS, `just test` runs the same tests with lldb.

`just nightly` runs both, the sanitizers over the conformance suite and over the million generated programs it checks against the reference interpreter.
